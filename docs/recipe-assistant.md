# Recipe editor assistant

Ask AI appears below the title in both Add Recipe and Edit Recipe. A recipe can still be saved with only a title. Type a request or use the system keyboard’s dictation microphone.

The chat belongs to the current editor draft. Closing and reopening it keeps the conversation, unfinished input, pending proposal and undo history. It is not saved as a shared conversation.

## Research and edits

Every submitted request searches online, including follow-ups. Apple Foundation Models resolves the latest request against the current draft and conversation, then creates a short search query for the requested component. Search uses the existing public recipe indexes from RecipeTin Eats, Budget Bytes and Skinnytaste. A public HTTPS recipe link pasted in a request is also read. This is a bounded publisher search, not an unrestricted search engine.

Pages must load successfully and contain structured ingredients and instructions. The assistant uses one relevant, complete source per response, exposes its actual URL, and must decline when the page does not support the request. URLs are never generated by the model. There is no model-memory fallback if online research fails. Foundation Models handles the local reasoning; only search keywords and normal page requests go to publishers. No paid model API or API key is required.

Changes are expressed as bounded ingredient/step additions, updates or removals and optional title, servings and duration edits. Existing row IDs and shopping category overrides are preserved. Photos, collections, tags, notes, original source URLs, recipe identity and reactions cannot be overwritten by the model. The proposal preview shows added, removed and changed content. Follow-ups refine the pending draft before Apply. Sources consulted are appended to Notes only when changes are applied.

Apply updates the unsaved draft; the recipe editor’s Save button commits it. Cancel in the recipe editor discards everything. Undo restores the exact prior draft, including its notes. Stale proposals and undo requests are rejected if the draft has since changed, preserving newer manual edits. Stopping or closing an active request cancels it and ignores late results.

## Sections and compatibility

Ingredients use existing recipe groups. Method steps now also have an optional section name, editable manually and displayed in the all-steps and full-screen method views. Online imports retain HowToSection headings so optional variants stay distinguishable during research. Section headings are stored as readable Markdown (`## Section` followed by a blank line) in the existing step text field. Older clients show readable headings; plain legacy steps remain unchanged. This does not change the Core Data or CloudKit production schema.

## Availability and limits

Requires Apple Intelligence on a supported device and internet access. The simulator can exercise the editor and composer but cannot validate live on-device generation. Unsupported/offline states preserve manual recipe entry. Requests are limited to 1,200 characters and research/context sizes are bounded for the on-device model. Complex or lengthy recipes may need smaller edits or manual entry. Model-generated adaptations still need user review; a citation is evidence of the consulted source, not a guarantee that every proposed edit is correct.

Image generation and photo attachments inside this chat are outside this first version. Existing text/photo import remains available separately.

## Verification

Local verification (2026-09-14): the complete domain module compiled and type-checked with Swift 6.1.2 in Swift 5 language mode. All 30 Swift Testing domain tests passed, including the seven assistant/section tests, using a direct test runner. Edited app, persistence and UI test files passed Swift syntax parsing. The standard SwiftPM runner failed with a generic fatal error in this Linux environment; a separate attempt at the six existing XCTest discovery tests stopped with signal 4. Those six tests, Core Data persistence tests, the Xcode simulator build/UI tests and live Apple Intelligence generation still require the macOS/device checks. Online smoke check: the RecipeTin Eats public search returned its naan recipe and that page supplied structured ingredients and method; the other two publishers returned HTTP 403 from this environment.


Domain regressions cover adding a component, preserving unrelated fields and identities, mixed index operations, invalid/duplicate edits, proposal refinement, source recording, stale changes and undo, and method-section round trips. Persistence regression covers sections and citations across a save/refresh. UI regression covers the chat opening, keyboard input surviving dismissal, and editor cancellation without saving.

Check ingredient/method sections on the recipe and another shared device. Turn off connectivity and verify an unsuccessful request leaves the draft intact.
